# 后续扩展约定

画师、同人角色、画面知识是内容分类，韩国原版、NAX 等是资源来源，两者独立。画师主入口保持韩国原版优先；新增来源不能悄悄替换其他来源的样图。

## 资源条目

界面消费 `web/sources.js` 提供的统一卡片：`id`、`section`、`title`、`model`、`prompt`、`note`、`photos`、`source`、`sourceUrl`。知识卡另带 `kind`，配图包含 `url` 和显示出处的 `label`。从原图收藏的完整元数据存入 `generation` 字符串，并贯穿备份恢复。

新增来源时增加独立转换函数，原始数据保持只读；解析出来的字符串作为文本显示，不作为 HTML、脚本或指令执行。不同模型不自动合并。相同模型与精确标签的个人收藏合并图片，不覆盖已有文字与备注；只按保守的大小写、空白和下划线规范化判断，不猜测相似画师名。

## 下载与更新

- `KoreanLibrary`：原作者图包的小目录和 HTTP Range 图片读取，绑定文件指纹与精确字节位置，拒绝整包响应。以后可以增加签过来源的远程小目录，但必须验证目录版本、允许的域名、偏移和源文件标识。
- `NaxLibrary`：下载小 ZIP 目录、筛选允许的图库、按需读图及条件更新。扩图库时同时修改来源映射和图库白名单，提升筛选缓存版本。
- `LocalPacks`：用户主动选择本机文件后建立字节目录。换机的文件关联仍需额外设计，不能假设文件 URI 不变。
- `AppUpdates`：应用 APK 的版本检查，与资源更新独立。以后发布时沿用包名与发行签名、提高 versionCode；密钥和密码不得进入公开仓库。

当前有各分区更新入口，但 NAX 的三个分区共用一份上游目录；韩国小目录和本地中文知识随 APK 发布。未建成远程发布的功能必须显示实际状态，不能假报更新成功。

## 原图读取和备份

`ImagePrompts` 本机解析图片中的文本和 alpha 隐藏信息，未找到时明确说明。今后新增 JPEG/WebP 或其他隐藏编码时，保持文件、像素、解压输出和嵌套层数的上限。

`GalleryStore` 保存内容哈希去重的原文件。缩略图单独生成，读取提示词始终使用原文件。图库文件和词库备份分别保存。

`LibraryBackup` 只通过系统选择器读写用户选定文件。前端负责结构验证，恢复使用同一数据库事务。新增字段时更新导出、导入、编辑和详情展示，并保持对旧备份的兼容。

这些是开发扩展位置，不是可执行第三方插件框架。未来若实现用户插件，应另行定义数据权限、联网范围、版本兼容和移除流程。

## 画风串与生图

先让用户挑选画师标签、调整权重并保存按模型区分的画风串草稿。草稿可带入图库原图的生成参数和角色提示词，也可复制给 NovelAI 网页使用。接入生图后，由用户在设备上配置凭据并主动提交，生成原图可再存入本机图库。
